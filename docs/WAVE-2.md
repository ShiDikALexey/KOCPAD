# Wave 2 — boundaries and reproducibility (`1.5.0-beta.2`)

Wave 1 made the app stop losing text. Wave 2 makes sure the native layer cannot be
talked into touching files it should not, keeps the UI responsive on slow disks and
makes builds reproducible. Everything lands on `beta`.

## Tasks

### 1. File-system sandbox (Rust)

The custom Tauri commands are not covered by the capability ACL, so they must enforce
the workspace boundary themselves.

- [x] `WorkspaceRoot` state (`Mutex<Option<PathBuf>>`), canonicalised when mounted.
- [x] `fs_set_root(root | null)` command; the storage backend calls it on choose,
      restore, mount and close.
- [x] Every scoped command (`list_tree`, `read_text`, `write_text`, `create_dir`,
      `read_binary`, `write_binary`, `rename`, `remove`, `exists`, `stat`) validates:
      - `..` components are rejected outright;
      - the deepest existing ancestor is canonicalised and must stay below the root;
      - symlinks are refused;
      - the root itself cannot be renamed or deleted.
- [x] Binary reads are capped at 25 MB.
- [x] `saveAs`/export uses a separate `fs_save_text` command: that path comes from the
      native save dialog, not from a note.

Acceptance: a crafted image path (`../../…` or an absolute path) and a symlink both
fail with a clear error; normal editing in the workspace is unaffected.

### 2. Async file commands

- [x] Scoped commands are `async` so Tauri runs them on its async runtime instead of
      the UI thread; a large folder or a slow network drive no longer freezes the
      window. (Blocking work inside an async command is not ideal; the next step
      would be `spawn_blocking`, tracked in WAVE-3.)

Acceptance: the tree of a folder with thousands of notes can be refreshed while
typing; the UI thread is not blocked (checked by hand on a big folder).

### 3. Single instance

- [x] `tauri-plugin-single-instance`: a second launch shows, restores and focuses the
      existing window instead of starting another process that would race on writes.
      The plugin is registered first, as its documentation requires.

Acceptance: double-clicking the exe twice leaves one window.

### 4. Reproducible Rust dependencies

- [x] CI runs `cargo generate-lockfile`, uploads `src-tauri/Cargo.lock` as an artifact
      and (once committed) fails when `Cargo.toml` changes without the lockfile.
- [x] The lockfile is committed, so release builds resolve the same versions.

### 5. CSP hardening

- [x] Production and development CSPs gained `object-src 'none'`, `frame-src 'none'`,
      `base-uri 'none'` and `form-action 'none'`. `script-src`/`default-src` stay as
      they are until a packaged-build check proves a stricter policy works (tracked
      for WAVE-3).

## Order and release

1. Rust sandbox + async commands + `fs_set_root`/`fs_save_text` + storage wiring.
2. Single-instance plugin.
3. `Cargo.lock` generated by CI, committed, lock check enabled.
4. CSP additions.
5. Docs updated; version bumped to `1.5.0-beta.2`; CI green; artifact published.
